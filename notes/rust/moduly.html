Moduły i widoczność

Jak pogodzić duży projekt z kompilatorem.

Pojęcia

  • crate — skompilowana jednostka: binarny (main.rs) albo biblioteczny (lib.rs).
  • package — jeden katalog z Cargo.toml; może zawierać kilka crate'ów.
  • moduł (mod) — drzewo porządkujące namespace wewnątrz crate'u.

Prywatność

Wszystko jest prywatne domyślnie. pub udostępnia element modułom zewnętrznym; dzieci widzą rodziców, rodzice nie widzą dzieci. Ścieżki względne zaczynasz od self::, super:: lub pełnej od korzenia crate'u. 

mod ogrod {
    pub mod krzewy {
        pub fn przycinaj() { }
    }
    fn podlewanie() { }     // prywatne — widzi je tylko ogrod i jego dzieci
}

Skracanie ścieżek — use

use ogrod::krzewy;
use ogrod::krzewy::przycinaj as przytnij;    // alias
use std::{collections::HashMap, fmt};         // zagnieżdżone
use std::io::prelude::*;                       // glob — ostrożnie, może kolidować

Konwencja: importuj rodzica modułu (use std::collections;) i wołaj collections::HashMap — widać źródło pochodzenia. pub use re-eksportuje wewnętrzną implementację pod publiczną ścieżką API.

Podział na pliki

Moduł front_of_house szuka kodu w front_of_house.rs (tam deklaruje podmoduły) albo w front_of_house/mod.rs. Nowoczesny styl: jeden plik z nazwą modułu obok katalogu z resztą.

Podsumowanie

Drzewo modułów organizuje kod, pub decyduje o widoczności (domyślnie prywatne), use skraca ścieżki w zasięgu. Zależności z crates.io importuje się dokładnie tak samo jak własne moduły.

Ćwiczenia

1. Dlaczego Rust wymaga osobnego use, skoro ścieżka jest pełna?

Ścieżka opisuje położenie w drzewie; use tworzy lokalny alias, żeby nie przepisywać prefiksów. To świadome rozdzielenie: widzisz, skąd coś pochodzi, bez zanieczyszczania globalnej przestrzeni nazw.

2. Struktura z polami prywatnymi, ale publiczną metodą wartosc() — co to daje?

Enkapsulację: pola bez pub pozostają dostępne tylko w swoim module. Zewnętrzny świat może korzystać z API metody, ale nie może nadpisać stanu — kontrola dostępu na poziomie pól.

3. Zagnieźdź importy use std::io; i use std::fs;.

use std::{fs, io}; — nawiasy klamrowe w use łączą wspólny przedrostek; tak samo grupuje się elementy wewnątrz jednego modułu.
