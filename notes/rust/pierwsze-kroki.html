Pierwsze kroki

Instalacja, narzędzia i pierwszy samodzielny program.

Narzędzia

Rust instaluje się przez rustup — menedżer wersji, który zarządza kompilatorem (rustc), menedżerem pakietów (cargo) i dokumentacją lokalną (rustup doc). Aktualizacja to rustup update.

Dwa poziomy pracy z kodem:

  • rustc main.rs — ręczna kompilacja pojedynczego pliku
  • cargo new nazwa — pełny szkielet projektu z manifestem Cargo.toml, katalogiem src/ i drzewem zależności

Cargo pilnuje konwencji: kod w src/, binarka startowa w src/main.rs, biblioteka w src/lib.rs. Build developerski (cargo run) jest szybki w kompilacji, release (cargo build --release) — szybki w działaniu (pełna optymalizacja).

Struktura programu

use std::io;  // sprowadza moduł do zasięgu

fn main() {
    println!("Podaj liczbę:");

    let mut input = String::new();          // domyślnie bindingi są niemutowalne
    io::stdin().read_line(&mut input)
        .expect("odczyt z stdin nie powiódł się");

    println!("To było: {input}");             // placeholder {} lub nazwany {input}
}

Kilka rzeczy naraz, które warto zapamiętać na start:

  • let x = ...; — wartość bez mut nie da się zmienić; kompilator odmówi.
  • read_line zwraca Result — może się nie powieść, więc trzeba obsłużyć błąd (expect / unwrap).
  • Wyrażenia kończą się średnikiem; blok { ... } bez średnika na końcu jest wartością zwrotną.
  • Dyrektywy kończące się ! (np. println!) to makra, nie funkcje.

Zewnętrzne crate'y

Dodanie zależności do Cargo.toml i use w kodzie w zupełności wystarcza. Np. generator losowy: 

// Cargo.toml: [dependencies] rand = "0.8"
use rand::Rng;

fn main() {
    let secret = rand::::thread_rng().gen_range(1..=100);
    println!("Los: {secret}");
}

Pętla do skutku

loop powtarza w nieskończoność i coś musi ją przerwać — zwykle break (ewentualnie z wartością zwrotną). To czysty mechanizm sterowania, bez warunków w nagłówku: 

loop {
    match odczytaj() {
        Ok(g) => {
            if g == poprawna { break; }
        }
        Err(_) => println!("nie ta wartość, spróbuj ponownie"),
    }
}

Podsumowanie

rustup zarządza zestawem narzędzi, cargo wszystkim w projekcie. Zmienne są domyślnie niemutowalne, błędy odczytu zwracane jako Result, a zależności deklaruje się w manifeście. Tyle wystarczy, żeby pisać pierwszy program.

Ćwiczenia

1. Czym różni się cargo build od cargo build --release?

Build domyślny (debug) kompiluje szybko i zostawia debugowanie, binarka działa wolniej. Wariant release włącza optymalizacje — dłuższa kompilacja, ale kod działa znacznie szybciej. Binarki lądują w target/debug/ i target/release/.

2. Co się stanie, jeśli spróbujesz przypisać nową wartość do zmiennej bez mut?

Kompilator zgłosi błąd: cannot assign twice to immutable variable. Napiętnowanie mut jest świadomą decyzją — bez niego kompilator gwarantuje, że wartość się nie zmieni.

3. Dlaczego read_line wymaga &mut input, a nie samego input?

read_line dokleja odczytany tekst do istniejącego String i musi go modyfikować — bierze więc pożyczkę mutalną (&mut). Pożyczka oddaje zmienną z powrotem po zakończeniu, bez przejęcia własności.
