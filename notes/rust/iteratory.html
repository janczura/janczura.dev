Domknięcia i iteratory

Funkcyjny styl bez utraty wydajności pętli.

Domknięcia

Anonimowa funkcja przechwytująca otoczenie. Przechwytuje albo przez pożyczkę, albo przez move (przeniesienie własności): 

let mnoznik = 3;
let potrojk = |x: i32| x * mnoznik;        // pożycza tylko do czytania

let napis = String::from("cześć");
let zjedz = move || println!("{napis}");   // napis przechodzi do domknięcia

Trzy poziomy apetytu (kompilator wybiera sam, move wymusza najwyższy): Fn czyta, FnMut modyfikuje, FnOnce zużywa przechwyconą wartość.

Iteratory

Iterator produkuje elementy kolejnymi wywołaniami next() (zwraca Option). Leniwy — nic nie robi do konsumpcji. Konsumenci: sum, count, collect; adaptery: map, filter, take, skip, enumerate, zip, rev: 

let v = vec![1, 2, 3, 4];

let sum_parzystych: i32 = v.iter()
    .filter(|&x| x % 2 == 0)
    .map(|x| x * x)
    .sum();                                  // 4 + 16 = 20

let nazwy: Vec<_> = v.iter().enumerate()
    .map(|(i, x)| format!("{i}: {x}"))
    .collect();

iter() → &T, iter_mut() → &mut T, into_iter() → T (zjada kolekcję). Adaptery nic nie kosztują: łańcuch rozpuszcza się w pętlę porównywalną z ręczną — to nie jest "wolny styl funkcyjny".

Podsumowanie

Domknięcia przechwytują kontekst (najlepiej jak najłagodniej, move gdy trzeba wynieść poza zasięg). Iteratory: adaptery leniwe + konsumenci zbierający wynik. Kod czytelniejszy niż pętla, koszt ten sam.

Ćwiczenia

1. Co wyświetli (1..=5).filter(|x| x % 2 == 0).count()?

2 — tylko 2 i 4. Zakres 1..=5 to iterator leniwy; count() jest konsumentem, który go wyczerpuje.

2. Zsumuj długości napisów z Vec<String> bez kopiowania.

v.iter().map(|s| s.len()).sum() — iter() pożycza elementy, len() tylko czyta. into_iter() zużyłby całe Vec.

3. Kiedy domknięcie MUSI użyć move?

Gdy ma przeżyć dłużej niż zmienne, które przechwytuje — np. zwracane z funkcji albo przekazywane do innego wątku. Bez move pożyczka nie przetrwałaby końca zasięgu.
