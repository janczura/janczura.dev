Serwer WWW: Axum

Routing, ekstraktory, stan aplikacji, warstwy — handler tylko tłumaczy HTTP na domenę.

Routing i start serwera

Axum 0.8: parametry ścieżki w klamerkach — /books/{id}, wildcard /assets/{*path}. Stara składnia :id panikuje przy starcie (hałaśliwie i wcześnie). Serwer startuje przez własny listener Tokio — stare axum::Server::bind zniknęło, a bezpośredni kontrol nad gniazdem przydaje się przy TLS i w kontenerze. 

use axum::routing::{get, post};
use tokio::net::TcpListener;

let app = Router::new()
    .route("/api/books", get(list_books))
    .route("/api/books/{id}", get(find_book))
    .route("/api/orders", post(place_order))
    .with_state(state);

let listener = TcpListener::bind("0.0.0.0:3000").await?;
axum::serve(listener, app).await?;

#[tokio::main] rozkręca runtime work-stealing (worker na rdzeń, wielowątkowy): handler czekający na bazę oddaje wątek innym żądaniom. Router<AppState> to router jeszcze bez stanu — typ pilnuje, żebyś nie serwował go przez pomyłką przed with_state.

Stan aplikacji

Jedna klonowalna struktura z serwisami za Arc — Klon stanu to kopiowanie wskaźnika, nie głęboka duplikacja. FromRef pozwala węższemu konsumentowi (np. integracji Leptos) wyciągnąć swoją część stanu, gdy handler chce całości: 

#[derive(Clone)]
pub struct AppState {
    pub leptos_options: LeptosOptions,
    pub inventory: Arc<InMemoryInventory>,
    pub jwt_secret: Arc<String>,
}

impl FromRef<AppState> for LeptosOptions {
    fn from_ref(state: &AppState) -> Self { state.leptos_options.clone() }
}

Handler to tylko tłumacz

Handler wyciąga, deleguje, opakowuje — zero logiki biznesowej. Ekstraktory (State, Query, Path, Json) robią parsowanie i walidację: Path::<Uuid> sam odeśle 400 gdy segment nie jest UUID-em, domena dostaje zawsze wartości poprawne. 

pub async fn list_books(
    State(state): State<AppState>,
    Query(filter): Query<BookFilter>,
) -> Result<Json<Vec<Book>>, ApiError> {
    let books = state.inventory.list_books(filter).await?;
    Ok(Json(books))
}

// 201 Created: status jako część zwracanej krotki
pub async fn place_order(
    State(state): State<AppState>,
    Extension(claims): Extension<Claims>,   // z middleware
    Json(body): Json<PlaceOrderRequest>,    // ciało KONIECZY listę parametrów
) -> Result<(StatusCode, Json<Order>), ApiError> {
    let order = state.orders.place_order(claims.sub, body.lines).await?;
    Ok((StatusCode::CREATED, Json(order)))
}

Ekstraktor zjadający ciało (Json) musi być ostatni — reszta tylko zagląda do requesta przed nim. Reguła egzekwowana na etapie kompilacji (dwa różne cechy: FromRequestParts vs FromRequest).

Błędy: jedno mapowanie na wszystko

Typ opakowujący DomainError implementuje IntoResponse; operator ? w handlerach konwertuje sam (przez From). Żaden handler nie widzi kodu statusu — zmiana mapowania dociera do wszystkich endpointów naraz. 

impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        let (status, msg) = match &self.0 {
            DomainError::BookNotFound(_)          => (StatusCode::NOT_FOUND,  self.0.to_string()),
            DomainError::InsufficientStock{..}    => (StatusCode::CONFLICT,    self.0.to_string()),
            DomainError::InvalidCredentials       => (StatusCode::UNAUTHORIZED, "authentication failed"),
            DomainError::Storage(_)               => (StatusCode::INTERNAL_SERVER_ERROR, "internal error"),
            // ...
        };
        (status, Json(json!({ "error": msg }))).into_response()
    }
}

Błąd storage oddaje klientowi generyczne zdanie, nie treść spod kaptura — komunikat bazy potrafi zdradzić nazwy tabel i kawałki zapytania. Pełną przyczynę zapisuje log; klient dostaje tylko to, co może naprawić.

Wywołania wychodzące

  • reqwest::Client budujemy raz i trzymamy w stanie — posiada pulę połączeń; nowy klient na żądanie wyrzuca pulę i dokłada handshake TLS do każdego wywołania.
  • Timeout na kliencie (nie na pojedynczych wywołaniach) — wychodzące wołanie bez limitu wisi dopóki pozwala OS, a kilka takich wyczerpuje pulę i kładzie serwis.
  • Błahy brak danych (okładka z OpenLibrary) → zwracamy Option, nie Result: niedostępny zewnętrzny serwis nie może zepsuć strony książki. Ostrzeżenie idzie do loga, widok renderuje się dalej.

Middleware: JWT przed handlerem

Middleware w Axum to zwykła async funkcja (State, Request, Next); zweryfikowane roszczenia wstrzykuje do extensions requesta, skąd bierze je Extension<Claims>. Ochrona na routerze, nie w handlerze — nowy endpoint nie prześlizgnie się bez zabezpieczenia. 

let protected = Router::new()
    .route("/api/orders", post(place_order))
    .route_layer(middleware::from_fn_with_state(state, require_auth));
  • route_layer chroni tylko zarejestrowane trasy; zwykły layer owinąłby też fallback i oddawał 401 zamiast 404 dla nieistniejących ścieżek.
  • Login zostaje poza chronioną grupą — klient nie ma jeszcze tokenu.
  • Validation::default() sam sprawdza przedawnienie tokenu.
  • Loguj ścieżkę, nie pełne URI — query string bywa pełen e-maili i przypadkowych tokenów.

Podsumowanie

Axum = routing w klamerkach + serve(listener, router) + state z Arc i FromRef. Handery cienkie: ekstraktory walidują, ciało ostatnie, status w krotce. Błędy mapowane w jednym IntoResponse. Client HTTP jeden na proces z timeoutem. Autoryzacja w route_layer, roszczenia przez extensions.

Ćwiczenia

1. Przeniosłeś Json przed Path — co mówi kompilator i dlaczego?

Błąd wspominający FromRequestParts: Json zjada ciało requesta, a ekstraktory po nim musiałyby czytać „po trupie". Reguła „ciało na końcu” jest wymuszana typami, więc pomyłka wychodzi przy budowie, nie w runtime'cie.

2. Czemu stanu nie da się przez pomyłkę serwować bez stanu?

Router<AppState> to typ informujący o braku stanu; serwowanie wymaga Router<()> po with_state. Handler oczekujący innego stanu niż dostarczony nie skompiluje się — gwarancja statyczna zamiast runtime'owej niespodzianki.

3. Klient z błędnym id w ścieżce dociera do Twojego handlera?

Nie. Path<Uuid> nie przeparsuje segmentu, Axum sam odpowie 400 i ciało handlera nigdy nie ruszy — stąd metoda domenowa dostaje wyłącznie wartości poprawne.
