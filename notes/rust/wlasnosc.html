Własność i pożyczanie

Model pamięci bez garbage collectora — serduszko języka.

Zasady

  1. Każda wartość ma dokładnie jednego właściciela.
  2. Gdy właściciel wychodzi z zasięgu, wartość jest zwalniana.
  3. Przypisanie lub przekazanie do funkcji przenosi własność (move) — stary uchwyt staje się nieważny.
let a = String::from("ala");
let b = a;        // własność przeszła do b; a jest nieaktywne
println!("{b}");
// println!("{a}"); ← błąd kompilacji: a nie żyje

Proste typy (i32, bool, char, krotki z nich) implementują Copy i są duplikowane bit po bicie — tu stary uchwyt nadal działa. Dla danych na stosie używamy jawnego .clone().

Pożyczki

Zamiast oddawać własność, pożyczamy: & (do czytania) albo &mut (do zmiany). Żelazna reguła: albo dowolna liczba pożyczek czytających, albo jedna mutująca — nigdy naraz. Dzięki temu nie ma data race'ów już na etapie kompilacji. 

fn dlugosc(s: &String) -> usize { s.len() }   // właściciel nic nie traci
fn dopisz(s: &mut String) { s.push_str("!"); }

let mut tekst = String::from("tak");
dopisz(&mut tekst);
println!("{tekst} (dł. {})", dlugosc(&tekst));

Nie wolno zwrócić referencji do wartości utworzonej wewnątrz funkcji — wskazówka zostałaby po zwolnionym buforze (tzw. wisząca referencja).

Wycinki

&s[0..5] to wycinek (slice) — pożyczka kawałka danych bez właściciela. Dla tekstów typ to &str; działa też na tablicach (&arr[1..3]). W funkcjach przyjmuj &str — akceptuje zarówno String, jak i literał tekstowy. 

fn pierwsze_slowo(s: &str) -> &str {
    match s.find(' ') {
        Some(i) => &s[..i],
        None => s,
    }
}

Podsumowanie

Jeden właściciel, move przy przypisaniu, pożyczki czytają albo modyfikują przez &/&mut, a reguła "wielu czytających XOR jeden mutujący" wygasza wyścigi. Wycinki pożyczają fragmenty. To ten model zastępuje garbage collector — koszt jest płacony w głowie, nie w czasie działania.

Ćwiczenia

1. Dlaczego let v = vec![1, 2]; let w = v; unieważnia v, a let x = 5; let y = x; nie?

Vec trzyma dane na stosie i ma wskaźnik w strukturze — kopiowanie wskaźnika zostawiłoby dwóch właścicieli tego samego bufora (podwójne zwolnienie), więc następuje move. i32 implementuje Copy, więc po prostu duplikuje wartość.

2. Czy można jednocześnie mieć &s i &mut s do tej samej wartości?

Nie. W jednym zasięgu mutowalna pożyczka wyklucza czytające (i odwrotnie). Kompilator pilnuje, by pożyczki nie nachodziły na siebie — w przeciwnym razie odczyt mógłby zobaczyć dane w trakcie zmiany.

3. Napisz funkcję zwracającą ostatni fragment tekstu po spacji — bez kopiowania znaków.

Wyszukać ostatnią spację i zwrócić wycinek: &s[i + 1..]. Sygnatura fn ogon(s: &str) -> &str — wynik pozostaje pożyczką oryginalnych danych, bez alokacji.
