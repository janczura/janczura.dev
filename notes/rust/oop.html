Obiektowość w Rust

Trait objekty, dyn, dispatch — polymorfizm bez dziedziczenia.

Części klasyczne, reszta inaczej

  • Dane razem z zachowaniem (struktura + metody) — jest. Enkapsulacja przez pub/prywatność — jest.
  • Dziedziczenia w rozumieniu klasycznym nie ma: zamiast hierarchii klas są cechy (trait'y) i kompozycja. Trait nie ma pól z danymi, implementacja nie „odziedzicza stanu".

Trait object i dyn

trait Rysunek {
    fn powierzchnia(&self) -> f64;
    fn nazwa(&self) -> &str;
}

struct Kolo { promień: f64 }
struct Prostokat { a: f64, b: f64 }

// obiekt typu "cokolwiek, co rysuje" — kolekcja różnorodnych typów
let szkice: Vec<Box<dyn Rysunek>> = vec![
    Box::new(Kolo { promień: 2.0 }),
    Box::new(Prostokat { a: 1.0, b: 4.0 }),
];

dyn Rysunek to typ o nieznanym rozmiarze — musi mieszkać za wskazówką (Box, &, Rc). W środku siedzi vtable: wskazówki na metody danego typu, rozwiązywane w biegu.

Dispatch statyczny vs dynamiczny

// statycznie: monomorfizacja, generowana wersja dla każdego typu, zero narzutu
fn policz<T: Rysunek>(r: &T) -> f64 { r.powierzchnia() }

// dynamicznie: jedna funkcja, ale skok przez vtable przy każdym wywołaniu
fn policz_dyn(r: &dyn Rysunek) -> f64 { r.powierzchnia() }
  • Generyk (impl Trait / <T: Trait>) — kompilator zna typ, generuje kod swoiście: szybko, ale koszt to ekspansja kodu i brak heterogenicznych kolekcji.
  • dyn — rozstrzygnięcie w biegu, wolniej i mniej optymalizacji, ale za to: Vec<Box<dyn Trait>>, dodawanie typów bez ruszania API.

Ograniczenia dyn

  • Trait musi być „obiektowo bezpieczny": metody bez Self w zwracanym typu, bez generycznych parametrów, bez self wartościowego w newralgicznych miejscach.
  • Stąd czasem dwa modele: jeden trait na „interfejs" (dyn-compatybilny) i drugi generyczny na wydajność.

Podsumowanie

Rust oddaje polimorfizm w dwóch smakach: generyki (statycznie, szybko, statyczne kolekcje) i dyn (dynamicznie, elastycznie, vtable). OOP-owy model „obiektów komunikujących się przez wiadomości" da się odtworzyć — bez dziedziczenia, z cechami zamiast klas bazowych.

Ćwiczenia

1. Dlaczego Vec<dyn Rysunek> nie przechodzi kompilacji, a Vec<Box<dyn Rysunek>> tak?

dyn Rysunek nie ma znanego rozmiaru (to „cokolwiek implementującego"), a Vec potrzebuje stałego rozmiaru elementu. Wskazówka (Box, &) ma znany rozmiar i prowadzi do danych dowolnej wielkości.

2. Kiedy wybrać generyk zamiast trait objectu?

Gdy wszystkie elementy kolekcji są tego samego typu i liczy się wydajność — dispatch statyczny bez vtable i z inliningiem. Gdy potrzebujesz heterogenicznej kolekcji lub API otwartego na nowe typy bez rekompilacji wywołujących — dyn.

3. Czym Rust zastępuje dziedziczenie „po klasie bazowej"?

Kompozycją z delegacją (trzymane pole + jawne wywołania albo wdrożenie cechy przez przekazanie) oraz cechami z domyślnymi implementacjami metod. Wspólny stan zostaje w strukturze, nie w „rodzicu".
