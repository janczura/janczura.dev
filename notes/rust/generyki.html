Generyki, cechy i lifetime'y

Abstrakcja bez utraty szybkości.

Generyki

Ten sam kod dla wielu typów; monomorfizacja — kompilator generuje osobną wersję pod każdy użycie, więc brak narzutu w działaniu: 

fn najwieksze<T: PartialOrd + Copy>(l: &[T]) -> T {
    let mut wynik = l[0];
    for &v in l { if v > wynik { wynik = v; } }
    wynik
}

Cechy (traits)

Trait opisuje wspólne zachowanie — kontrakt. Typ implementuje go przez impl: 

trait Opisowy {
    fn opis(&self) -> String;

    fn naglowek(&self) -> String {         // implementacja domyślna
        format!("### {}", self.opis())
    }
}

impl Opisowy for Film {
    fn opis(&self) -> String { self.tytul.clone() }
}

Ograniczenia generyczne (trait bound) — trzy równoważne zapisy: fn f<T: Suma>(x: T), fn f(x: impl Suma) (sugar) albo &dyn Suma (dynamiczny dispatch). Przy wielu boundach czytelniej wygląda sekcja where.

Lifetime'y

Adnotacje przy referencjach mówią jak długo pożyczka pozostaje ważna — chronią przed wiszącymi wskaźnikami. Nazwy ('a) nie zmieniają czasu życia, tylko opisują zależność: 

// zwrócony wycinek pozostaje ważny najdłużej jak najkrótsza z pożyczek
fn krotsze<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() < y.len() { x } else { y }
}
  • Większość sygnatur nie potrzebuje adnotacji — elizja wstawia reguły automatycznie (1 wejście → 1 wyjście).
  • Struktury trzymające referencje wymagają pola lifetime: struct Koszulka<'a> { material: &'a str }.
  • 'static: literały tekstowe żyją cały czas trwania programu.

Podsumowanie

Generyki usuwają duplikację, traits opisują zachowania (z domyślnymi metodami), bound'y ograniczają typy do tych, które potrafią to, czego potrzebujesz. Lifetime'y dokumentują pożyczki — zwykle wyliczalnie, bez pisania ich ręcznie.

Ćwiczenia

1. Dlaczego impl Trait w argumencie to nie to samo co Box<dyn Trait>?

impl Trait = monomorfizacja (osobna wersja funkcji per typ, statyczne wiązanie, brak alokacji). Box<dyn Trait> = dynamiczny dispatch przez tabelę metod (vtable) — jeden kod dla wielu typów, koszt wskaźnika i pośredniego wywołania.

2. Co znaczy bound T: Clone i kiedy jest potrzebny?

"T musi umieć się sklonować". Potrzebny, gdy wewnątrz funkcji wywołujesz x.clone() — bez bounda kompilator nie wie, czy typ to potrafi. Analogicznie Debug, PartialOrd, itd.

3. Struktura przechowująca pożyczony &str — co dopisać?

Parametr lifetime: struct Naglowek<'a> { tytul: &'a str }. Obowiązuje ona w całym implu typu; wymusza, by obiekt nie przeżył tekstu, na który wskazuje.
